# Spec: the `steject-starters` repo

A separate public repo, **aadvik7/steject-starters**, holds full starter projects: a reference solution with tests, and a page that says what a student learns. The STEJECT app's gallery will load its index, so new starters ship without an app release.

The built-in gallery (`app/starters/starters.js`) stays as is: short ideas that the AI builds. Starters in this repo add a **finished, tested example** a student can open, compare with, or learn from.

## Layout

```
steject-starters/
├─ README.md                 what this is, how to add a starter
├─ index.json                generated by the validator; the app reads this
├─ starters/
│  └─ <id>/                  one folder per starter, named after its id
│     ├─ starter.json        metadata (below)
│     ├─ project.txt         the full project in STEJECT manifest format, with tests
│     └─ README.md           what you'll learn, difficulty, how to run and test
└─ .github/workflows/validate.yml
```

## `starter.json`

```json
{
  "id": "todo-cli",
  "title": "To-do list in the terminal",
  "level": "beginner",
  "lang": "Python",
  "size": "small",
  "time": "1 to 2 hours",
  "idea": "A Python command-line to-do app: add, list, complete and delete tasks, saved to a JSON file. Use argparse, and add pytest tests for the task functions.",
  "learn": ["reading and writing JSON", "argparse subcommands", "writing pytest tests"],
  "tags": ["cli", "files"]
}
```

| Field | Rule |
|---|---|
| `id` | lowercase letters, digits and `-`; same as the folder name; unique |
| `title` | 1 to 40 characters |
| `level` | `beginner`, `intermediate` or `advanced` |
| `lang` | the main language, e.g. `Python`, `HTML/CSS/JS` |
| `size` | `small` (3 to 6 files) or `medium` (5 to 9 files) |
| `idea` | 20 to 400 characters, works offline (no keys, accounts or paid services) |
| `learn` | 1 to 6 short strings |
| `time`, `tags` | optional |

## `project.txt`

The reference project as a STEJECT manifest (`=== PROJECT ===`, `=== FILE ===`, `=== COMMIT ===`). It must:
- parse with the STEJECT parser (same rules as the app: safe relative paths, every file before its COMMIT line),
- include at least one **test file** and a `README.md`,
- pass the STEJECT secret scan,
- have between 2 and 8 commits that tell the story of how it was built.

## `README.md` (in the starter folder)

Must have these headings: `## What you'll learn`, `## Difficulty`, `## Run it`, `## Test it`.

## `index.json`

Generated, never edited by hand:

```json
{ "version": 1, "generated": "2026-10-12", "starters": [
  { "id": "todo-cli", "title": "…", "level": "beginner", "lang": "Python", "size": "small", "idea": "…", "learn": ["…"],
    "project": "starters/todo-cli/project.txt", "readme": "starters/todo-cli/README.md" } ] }
```

The app fetches `https://raw.githubusercontent.com/aadvik7/steject-starters/main/index.json` (that host is already on the app's network allowlist). Paths are relative to the repo root. Fields the app doesn't know are ignored, so the format can grow.

## Validator

`scripts/validate-starters.js` in the STEJECT repo checks a starters folder with the real STEJECT parser and secret scan:

```bash
node scripts/validate-starters.js path/to/steject-starters            # check
node scripts/validate-starters.js path/to/steject-starters --index    # check and write index.json
```

It prints one line per problem and exits with code 1 if anything is wrong. The starters repo's CI downloads `app/js/core.js` and the validator from STEJECT `main` and runs it on every pull request, so both repos always agree on the format.

A ready-to-copy version of the repo, with one example starter and the CI workflow, is in [`templates/steject-starters/`](../templates/steject-starters/).

## Creating the repo

1. On GitHub, create a **public** repo named `steject-starters` with no README.
2. Copy everything inside `templates/steject-starters/` into it (including `.github`), commit and push. STEJECT itself can do this: *Open folder* → pick the template folder → push as a new repo.
3. Enable Actions. Every pull request is validated automatically.
